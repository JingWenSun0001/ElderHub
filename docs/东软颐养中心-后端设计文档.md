## 3. 统一规范

### 3.1 统一响应 Result

```java
@Data
@AllArgsConstructor
public class Result<T> {
    private Integer code;
    private String msg;
    private T data;

    public static <T> Result<T> success(T data) {
        return new Result<>(200, "success", data);
    }

    public static <T> Result<T> success() {
        return new Result<>(200, "success", null);
    }

    public static <T> Result<T> error(Integer code, String msg) {
        return new Result<>(code, msg, null);
    }
}
```

### 3.2 分页对象 PageResult

```java
@Data
@AllArgsConstructor
public class PageResult<T> {
    private Long total;
    private List<T> records;
}
```

### 3.3 逻辑删除

所有含 `is_deleted` 字段的表，MyBatis-Plus 全局配置：`0=显示，1=隐藏`。
DO类中属性命名为 `deleted`，通过 `@TableField("is_deleted")` 映射。

### 3.4 JWT 认证

1. 登录成功 → 生成 token（payload: userId, username, roleId）
2. 前端请求头 `Authorization: Bearer <token>`
3. `JwtInterceptor` 解析 token，userId/roleId 存入 `ThreadLocal`
4. 角色校验：管理员(roleId=1)全放行；健康管家(roleId=2)仅 `/nurse/**` 接口，数据按 `customer.user_id = 当前userId` 隔离

```java
public class JwtUtil {
    public String createToken(Integer userId, String username, Integer roleId);
    public Claims parseToken(String token);
}
```

### 3.5 当前用户上下文 UserContext

```java
public class UserContext {
    private static final ThreadLocal<LoginUserVO> HOLDER = new ThreadLocal<>();

    public static void set(LoginUserVO user) {
        HOLDER.set(user);
    }

    public static LoginUserVO get() {
        return HOLDER.get();
    }

    public static void clear() {
        HOLDER.remove();
    }
}
```

## 4. 数据库设计

> 表名/字段名小写字母或数字，单词间下划线分隔；表名不用复数；必备三字段 id、create_time、update_time；小数用decimal；是与否用is_xxx。
索引命名：主键pk\_字段名，唯一索引uk\_字段名，普通索引idx\_字段名。

### 4.1 用户与权限（4张）

| 表 | 关键字段 | 索引 |
| --- | --- | --- |
| `user` | id, username, password, nickname, sex, phone_number, email, role_id, create_time, update_time, is_deleted | uk_username, idx_role_id |
| `role` | id, name, create_time, update_time, is_deleted | - |
| `menu` | id, title, icon, path, parent_id, menus_index | idx_parent_id |
| `role_menu` | id, role_id, menu_id | idx_role_id, uk_role_menu |

### 4.2 床位与房间（3张）

| 表 | 关键字段 | 索引 |
| --- | --- | --- |
| `room` | id, room_floor, room_no, create_time, update_time | uk_room_no |

**入住登记关键逻辑** (`saveCustomer`):

2. 年龄 = 当前年 - 出生年（由birthday计算）
3. buildingNo 固定606
4. 选房间 → 联动查空闲床位（bedStatus=FREE）
5. 插入 customer
6. 更新 bed.bedStatus = OCCUPIED
7. 插入 bed_details（startDate=checkinDate，endDate=null）

**删除客户关键逻辑** (`removeCustomer`):

1. customer 逻辑删除
2. 当前 bed.bedStatus = FREE
3. 当前生效 bed_details 逻辑删除

**修改客户关键逻辑** (`updateCustomer`):

- 若 expirationDate 变更 → 同步更新当前生效 bed_details 的 endDate

**设置护理级别关键逻辑** (`setCustomerLevel`):

1. 校验：客户当前 levelId 必须为 null
2. 更新 customer.levelId
3. 批量插入 customer_nurse_item：该级别所有项目

    - buyTime = 当前日期
    - nurseNumber = 1（默认）
    - maturityTime = 当前日期 + 3个月

**移除护理级别关键逻辑** (`removeCustomerLevel`):

1. customer.levelId = null
2. 逻辑删除该客户当前 levelId 下所有 customer_nurse_item

**项目状态判断** (`CustomerNurseItemVO.status`):

- maturityTime < 当前日期 → 到期
- nurseNumber ≤ 0 → 欠费
- 否则 → 数量正常/未到期

**续费关键逻辑** (`renewItem`):

- nurseNumber = 原有数量 + 新增数量
- 更新 maturityTime

## 7. 核心业务规则速查

| 场景 | 规则 |
| --- | --- |
| 入住登记 | 楼栋固定606；年龄=当前年-出生年；合同到期≥入住时间；床位必须空闲 |
| 删除客户 | 级联：customer逻辑删 → bed改空闲 → 当前生效bed_details逻辑删 |
| 床位调换 | 当天办理；目标床必须空闲；旧床失效+新床生效；同步更新customer房间床位 |
| 退住审核通过 | 正常/死亡退住→bed空闲；保留床位→bed不变 |
| 外出审核通过 | bed→外出；回院登记后→bed→有人 |
| 护理项目停用 | 自动从nurse_level_item移除；**不影响**客户已购customer_nurse_item |
| 设置护理级别 | 客户必须无级别；批量插入该级别所有项目，数量默认1，到期默认3个月 |
| 更换护理级别 | 先移除旧级别（级联删客户项目），再设置新级别 |
| 录入护理记录 | 同时扣减客户该项目nurseNumber |
| 管家数据隔离 | 所有/nurse接口只操作customer.userId=当前登录用户的客户 |
| 用户初始密码 | 新增用户密码=手机号后6位 |
